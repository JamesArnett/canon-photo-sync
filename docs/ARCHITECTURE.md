# Architecture

`main.ts` composes the loopback HTTP listener, session authentication, registry/configuration store, directory policy, engine, preview worker and durable push outbox. The PWA is static HTML, CSS and browser JavaScript. Backend code uses strict TypeScript. The default dashboard polls every five seconds while visible.

A stable serial maps to an internal UUID. Camera configurations can be removed while history and serial mappings persist. Each poll identifies the camera, enumerates incremental records from the adapter and gates downloads on the current sighting set. For an explicit estimate before starting, save a paused camera and choose **Estimate matching media**. The estimate counts selected media on the camera. The scheduler bounds global and per-camera concurrency and snapshots destination settings for active jobs. Unreachable cameras reconnect independently with jittered backoff.

A source fingerprint combines serial, storage, adapter key, path, source size, capture or modification timestamp, and checksum when supplied. A SHA-256 content check collapses duplicates across cards of the same camera. If firmware reuses all available source metadata for different bytes, an adapter must provide a stronger key to distinguish them. Explicit reimport queues a separate copy when the original is visible.

Each download streams into a unique partial on the destination filesystem. It checks the supplied size and checksum independently and records which checks were possible. The engine syncs the staged file, records publication intent, publishes with an atomic exclusive hard link, syncs the containing directory, records success and removes the partial. A restart recognizes a matching staged/final inode. An ambiguous publication stops in review and keeps the staged file for reconciliation. An external workflow can move completed files without affecting historical deduplication. Date folders use the capture timestamp if the adapter provides it, then the file modification timestamp, then queue creation time. All folder dates use UTC. The Canon adapter supplies modification time in this version.

SQLite uses WAL with synchronous FULL on supported local filesystems. Node 22.13+ uses node:sqlite. The Node 20 path uses libsql with platform packages distributed through npm. The DSM ABI and local Btrfs hard-link/fsync semantics need hardware testing. The schema uses version 1 and additive initialization. Move to a supported Node LTS before unattended use.

Push submission is independent of synchronization. Pending delivery rows and operational events persist. The preview worker accepts bounded JPEGs from an adapter, and can reuse an already-small JPEG original, with file-type placeholders for unavailable media; it has bounded pending work.
