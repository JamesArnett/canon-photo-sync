# Security

The trust boundaries are the LAN reverse proxy, the registered OIDC issuer, the unprivileged daemon, approved camera networks, and explicitly authorized import roots. Threats include untrusted camera metadata, a stolen session or push endpoint, malicious web origins and an upstream hostname resolving to an unintended host.

- Serve the app only through a trusted internal HTTPS DSM hostname. The backend binds IPv4 loopback and validates Host, Origin and forwarded host/scheme when present. The proxy must strip incoming forwarding headers. Local users/processes capable of reaching the backend must be trusted as part of this deployment.
- Authenticated requests require an OIDC session. Authorization defaults to deny and checks configured stable subjects and signed groups. Authorized users have the same administrative access. Sessions are random, server-side, rotated at login and expire on logout, restart or timeout. State-changing API calls require same origin and a per-session CSRF token. CSP blocks inline scripting, framing and cross-origin connections.
- Camera URLs have a configured origin, DNS resolves into explicit CIDRs and a local address class, DNS answers are pinned per request, and redirects are rejected. TLS verifies host certificates, including operator-configured CA roots. Canon Digest credentials require verified HTTPS. HTTP camera connections trade confidentiality and on-path identity assurance for compatibility. Use a trusted isolated camera network and HTTPS wherever possible.
- Destination browsing and import paths use canonical paths against an allowlist and reject symlinks. Use DSM ACLs to stop untrusted local users and concurrent workflows from swapping approved directories during a transfer. Node's portable filesystem APIs leave a time-of-check/time-of-use window for a local process that can rename a trusted path component. Keep imported and private paths separate. Original files are never exposed via static routes.
- Service state and credentials stay in private files and private directories. Encrypt backups at rest under existing NAS backup policy. The HTTPS push endpoint and keys are checked against a fixed provider allowlist and pinned public DNS results. Push subscription secrets and existing camera credentials are absent from API reads. Removing a user from the OIDC allowlist requires restart. Remove that user's registered devices as part of offboarding by using a trusted backup/maintenance procedure.
- Install adapter modules only from code you control. The adapter runs with daemon permissions. Production has no fixture entry point. No NAS credentials are sent to cameras. Cloud tests use generated media and synthetic providers.
- Audit the dependency lockfile regularly. Provider supply chain, local-admin compromise, hardware behavior, physical DSM filesystem permissions, browser security and public exposure still require deployment review.
