# Synology SSO Server

Synology documents OIDC in current SSO Server. Treat DSM 7.2+ and an installed package with **Enable OIDC Server** as the starting point. The exact installed DSM build, package version, claims, local accounts and MFA behavior could not be verified remotely. DSM's own OIDC client page is for signing into DSM, whereas this app registers as a client in SSO Server. [SSO Server overview](https://kb.synology.com/en-us/DSM/help/SSOServer/sso_server_desc?version=7) · [Synology configuration guides](https://kb.synology.com/en-global/DSM/tutorial/sso_server_config_guides)

1. In Package Center install or update **SSO Server**. Open it, choose **General Settings**, select local users or the account source that includes the intended users, and set its trusted internal HTTPS external address. Synology's General Settings explains how this address determines the well-known URL. [General Settings](https://kb.synology.com/en-global/DSM/help/SSOServer/sso_server_general_setting)
2. Under **Service**, enable OIDC and save. In **Applications**, add an OIDC confidential client for Canon Photo Sync and register the exact redirect URI `https://<app-host>/auth/callback`. Copy the client ID and secret. Store the secret in the private secrets file. [SSO service](https://kb.synology.com/en-global/DSM/help/SSOServer/sso_server_service)
3. Read the provider's HTTPS well-known document. Use its exact `issuer` and optionally the published discovery URL. Configure the exact stable signed token subjects in `oidc.subjects`, or use exact signed ID token groups with `groupsClaim` if supported. Verify the mapping using tools under the NAS operator's control and keep tokens private. Groups from unsigned or browser-submitted sources grant no access.
4. The app requests authorization code flow, state, nonce, a signed ID token and S256 PKCE by default. Run `doctor`, then test signing in with an authorized and an unauthorized account. If discovery fails, compare the issuer, JWKS URL and HTTPS trust. If PKCE alone is unsupported, document the installed version and set `pkce:false` explicitly while retaining confidential client authentication, state and nonce. Set `clientAuth` to the registered mode, either `client_secret_post` or `client_secret_basic`. A provider without signed ID tokens is incompatible.
5. Confirm provider-managed MFA with the selected account source. The app signs out its own session by default. Set `postLogout` only if the installed provider advertises an end-session endpoint, accepts this client logout request and registers the exact HTTPS return URL. The app always expires its own cookie and invalidates the server-side session.

An empty allowlist fails daemon startup. If the installed SSO package or NAS OS can't supply the required OIDC features, run a supported package or wait for a supported deployment. Production always requires authenticated and separately authorized sessions.
